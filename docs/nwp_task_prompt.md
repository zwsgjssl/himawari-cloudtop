4. 解析を書く。最初に 12 枚を全部見てから、図どうしを重ね合わせて立体的に考える(1 枚の図だけで判断しない)。
   - 図を合わせて読むこと(例。これに限らない):
     ・500hPa の谷・寒冷渦の位置と、850hPa の相当温位の集中帯(前線)・暖湿気の舌 → 谷の東側(前面)にある前線上の低気圧は発達しやすい。谷が前線に近づく(位相がそろう)ほど、発達と CB の可能性が高い。
     ・500hPa の寒気(-15℃以下など)の下に 850hPa の暖湿気(高い相当温位・湿数小)が入る所 → 成層が不安定 → CB・雷の可能性。
     ・200・250・300hPa のジェット軸と等風速線の混み方、AUPA20 の圏界面の高さの急変(圏界面の折れ込み)、500hPa の谷の深まり → CAT。ジェットの曲がる所(谷の底・尾根の頂)も CAT。
     ・解析(AUPQ・AUPA)と 24 時間予想(FUPA・FSAS24)・FXJP854 の 12・24 時間を比べて、谷・ジェット・前線の動き(東進の速さ、深まる・浅まる)を書く。
     ・平面の図で見つけたジェット・谷・前線・湿域が、FXJP106 の断面のどこ(どの区間・どの FL)に出ているかを確かめる(例: AUPQ35 の等風速線の混みと断面の鉛直シアーの破線、AUPQ78 の湿域と断面の湿域、前線と断面の相当温位の混み)。
     ・AXJP(今の実測の断面)と FXJP106(6・12 時間後の予想の断面)を比べて、ジェットの芯の高さ・強さ、圏界面、前線面(等温位線の傾き)、湿域がどう変わるかを読む。
     ・2 つ目のモデルとして UKMET と比べる(/tmp/obs/ukmo/ の一番新しい回の t0 と f12): ジェットの位置・強さ・高さ、強いシアーの所、圏界面が、気象庁の図(AUPQ・AUPA・FUPA・FXJP106)と合っているか。
       合っていれば確かさが高い、違えば「モデルで分かれている = 確かさが低い」と書く(どちらかに決めつけない)。
     ・地上の低気圧・前線(SPAS・FSAS24)と上空を縦に結び付ける: 500hPa の谷との位置関係(谷の前面か・真下か = 発達中か・最盛期か)、850hPa の相当温位の集中帯と地上の前線が合っているか、FSAS で低気圧が深まる所と FUPA502 の谷の深まりが合っているか。等圧線の混み = 地上の強風・到着地の横風。
   - 各図の行でも、他の図から分かったことを使ってその図の意味を書き、どの図を合わせたかが分かるようにする(例:「・①500hPa の谷(朝鮮半島付近)。FXJP854 の前線帯がその東側(前面)にあり、前線上の低気圧が東シナ海〜本州南岸で発達しやすい」)。
   - 各図(charts): その図から読み取れる運航上の要点を 2〜4 行(重要な物から。少なくてよい。「・」で始まる箇条書き。行は改行 \n で区切る)。図の特定の場所を指す行は、「・」のすぐ後に ①②③… の番号を付け、同じ番号の印(marks)をその図に付ける。
     行には、なぜそこが大事かを図の見方と一緒に書く(例:「・①相当温位の線が混んでいる帯(318〜336K)= 前線帯。本州南岸〜九州の南」「・②等風速線が混んだ所 = ジェットのそばのシアー → CAT」)。
   - どの行(各図の行・総括)も「だから何」まで書く(ユーザー「だから何なのかってところまであるといい」)。図で見えた物 → それで今後どうなるか → 運航で何に気を付けるか(どの区間・FL・時間帯に、揺れ・CB・強い向かい風/追い風・地上の強風や横風・天気の崩れがあるか、または無いか)、の順に 1 行で。
     良い例(ユーザーが良いと言った物):「・①低気圧は樺太北部で 972hPa とほぼ停滞。FUPA502 ①の寒冷渦の真下に入り最盛期。北海道の等圧線の混みは緩み、地上の西風は弱まる」
     悪い例(何がどうなるのか分からない):「・②台湾〜八重山の 336〜342K の暖湿気。⑤朝鮮半島の南〜東シナ海北部は 300K 以下の乾いた寒気」
       → 直し方: 暖湿気・寒気が「あるだけ」で終わらせず、他の図と合わせて、それで何が起きるか(例: 上空の寒気・谷が来るか、前線が近づくか → CB が立つか立たないか、雲・雨の範囲、雲頂の高さ、乾いた寒気なら晴れて揺れも少ない など)と、どの空港・航空路に関係するかまで書く。
       何も起きない事・影響が無い事(「CB の心配は小さい」「CB にはならない」「揺れの心配は小さい」など)は書かない(ユーザー「影響が無い時は書かなくていい。CB が発生する可能性があるときだけ書いて」2026-10-18)。1 行に 2 つの事を詰めず、番号ごとに行を分ける。
   - 書かない事(ユーザー「こんな当たり前のことは書かなくていい」「当面影響がないものも省いていい」):
     ・当たり前の事: 偏西風で「西行便は向かい風・東行便は追い風」のような、いつもの事。風は、いつもより特に強い・弱い・向きが違う所、揺れにつながる所だけ書く。
     ・今後 24 時間に日本の空港・国内の航空路に影響しない物: 上流(モンゴル・華北など)の谷・渦・強風帯で 24 時間以内に来ない物、国内線の航路から外れた所(千島〜アリューシャン・北日本の東の遠い洋上・南の遠い洋上など)の強風帯・低気圧。「16日以降の崩れのもと」のような先の話も書かない(その行・印・総括の行ごと省く)。
   - 見る先は 24 時間先まで(ユーザーの希望。FXJP854 の 36・48 時間の段は使わない)。
   - 全体の総括(summary): 12 枚を合わせた、今後 24 時間の運航上の要点を、エリアごとにまとめる(ユーザー「総括はエリア毎でまとめてくれると見やすい」)。
     形: 1 行目「・【全体】…」(大きな流れ = ジェットの位置・強さ・高さ、谷・寒冷渦・低気圧・前線の動き。1〜2 行)、続けて、気を付ける事があるエリアだけを この順に 1 行ずつ(大事な事が多いエリアは 2 行まで):
       「・【北海道】…」「・【東北】…」「・【関東・中部】…」「・【関西・中国・四国】…」「・【九州】…」「・【沖縄・南西諸島】…」
     各エリアの行には、その空域・空港に関係する事だけを書く: CAT(どの FL・時間帯)、CB・雷(雲頂)、地上の強風・横風・天気の崩れ、向かい風・追い風(いつもより特に強い・弱いときだけ)。「だから何」まで(4 の決まりと同じ)。
     気を付ける事が無いエリアは、その行ごと書かない(ユーザー「影響が無い時は書かなくていい」)。会社経路の区間で国外・洋上にかかる所(東シナ海・伊豆諸島の南など)の事は、関係するエリアの行に入れる(例: 東シナ海の CAT は【九州】、伊豆諸島の南の CB は【関東・中部】)。
     簡潔に(ユーザー「重要な部分に焦点を当てて簡潔に」2026-10-18): 1 行 = 1 つの事。「どこ(路線・区間・FIX)・どの FL・いつ・何(強さ)・だから何」を 1 行 60〜100 字くらいで。根拠の図の名前や数字は大事な 1〜2 個だけ。
     総括は全部で 3〜7 行。揺れ・CB・横風など運航に効く物を大きい順に。いつもどおりの事、影響が無い事は書かない。

       ・断面図(FXJP106・AXJP)の CAT・ジェットの芯 = シアーの破線・等風速線(120kt など)で囲まれた所を fill。囲みが無ければ、その線の束を snap。
     最後に check で全部の印をまとめて描き、印ごとの拡大を Read で見て、線・点々・記号からはみ出し・ずれ・取りこぼしが無いか確かめる。
     日本付近と運航に関係する所を優先する。図の外や凡例・題名の欄には付けない。
   - 答え合わせ(check。アプリには出さない内部の記録。ユーザー「照合は表示せずに内部的にやってくれればいい。間違ってた部分は今後の解析に活かしてほしい」):
     ここまで(各図の解析と総括)を書き終えてから、ref_*.png(FBJP = 国内悪天予想図、全国航空気象解説報の国内空域・福岡FIR。気象庁の予報官が作った物)を Read で見て、自分の解析と照らし合わせる。
     あわせて /tmp/obs/obs/<UTC の日>.json の taf(主な空港の TAF。予報官の空港の予報。新しく出た物だけが出た時刻の hours に入っている)の最新を見て、
     空港の風・視程・雲・雨・雷・CB の予想が、自分の解析(総括の空港の行・SPAS・FSAS24・断面図)と合っているかを照らし合わせる(TAF の読み方: TEMPO・BECMG・PROB の時間帯にも注意)。
     (1) 違う所・自分の解析に無くて資料にあった大事な点(CB・CAT・前線・低気圧の位置や高さ)は、図をもう一度見直す。図の読み間違い・見落としなら、その図の行・総括・印を直す(資料の文をそのまま写さず、図から読める言葉で書く)。図から読めないことは足さない。
     (2) check に 3〜6 行(「・」で始まる箇条書き)で記録する: 一致した所、違った所とその理由(読み間違い・見落とし・判断の違い・資料の時刻の違い)、直した所。資料が無い・読めないときは「資料がありませんでした」。
     (3) 読み間違い・見落としが分かったときは、次からの解析に生かすため、nwp_ai/lessons.md を書き直す: 日付や場所だけの事実ではなく、次も役に立つ読み方の注意として 1 行ずつ(例「・秋の前線上の CB は雲頂 FL330〜390 と高い。AXJP・FXJP106 の湿域の上端と圏界面を見て CB の高さを低く見積もらない」)。
         行の頭に足した日(YYYY-MM-DD)を付ける。同じ内容はまとめ、古くて当てはまらなくなった物は消し、全部で 30 行まで。間違いが無かった回は書き直さなくてよい。
5. main の nwp_ai/ai.json に、次の形の JSON(UTF-8)で書く:
   {"base": "<回(高層の図の base)と同じ文字列>", "model": "Claude(定時の解析)", "at": "<今の UTC。YYYY-MM-DDTHH:MMZ>", "summary": "<総括>", "claims": [ {予想の要点}, … ], "verify": "<事後検証のまとめ>", "charts": {"spas": "...", "fsas24": "...", "aupq78": "...", "aupq35": "...", "aupa25": "...", "aupa20": "...", "fupa502": "...", "fupa302": "...", "fupa252": "...", "axjp": "...", "fxjp106": "...", "fxjp854": "..."}, "marks": {"aupq35": [ {印}, … ], …}, "lm": {"<図の id>": "<charts.json のその図の lm をそのまま>", …(解析した全部の図)}, "check": "<答え合わせ>", "refs": ["<照らし合わせた資料と発表時刻。例 FBJP VALID 15日12Z・TAF RJTT 150500Z>", …]}
   - lm は、アプリが「この解説はこの版の図を見て書いた」と分かるために使う。charts.json の lm の文字をそのまま入れる。
   - charts.json に無い図の id は入れない。JSON として正しいことを `python3 -m json.tool` で確かめる。
   - 同じ中身を nwp_ai/history/<回の base から : を除いた物>.json(例 2026-10-15T0000Z.json)にも書く(次の回の事後検証が読む)。history は新しい 8 個だけ残し、古い物は消す。
6. nwp_ai/ai.json・nwp_ai/history/・nwp_ai/verify_log.md と(書き直したときは)nwp_ai/lessons.md だけを commit して main に push する(コミットのメッセージ例: "nwp ai <base>")。ほかのファイル・ブランチには触らない。push の前に `git fetch origin main` して rebase する。競合したら pull --rebase してからもう一度 push する。
7. 最後に、何の回(base)をどう解析したか、事後検証の結果、照らし合わせで直した所と lessons.md に足した注意を 1〜4 行で報告して終わる。途中で終わったときは、その理由を 1 行で報告する。

## 一部の更新(2 の (B) のとき)
高層の回は同じで、一部の図だけが新しくなったときは、全部をやり直さず、新しくなった図とそれに関係する所だけを直す(使う量を抑えるため)。
- 1・2 と同じように nwp-img・nwp-obs を取り出し、lessons.md を読む。事後検証(2.5)と答え合わせ(check)はしない(全体の解析のときにする。verify・check・refs は前のまま残す)。
- 新しくなった図を Read で見る(拡大して読む。3 と同じ)。前の版とどう変わったか(低気圧・前線の位置や深さ、断面のシアー・湿域・CB の高さ)を、ai.json の前の解説・印と比べて確かめる。
  関係する他の図(高層の解析・予想、UKMET の一番新しい回)は、必要な所だけ見直す。全部の図を見直さなくてよい。
- 直す物:
  ・新しくなった図の charts の行(2〜4 行。4 と同じく「だから何」まで書く)と marks(座標の決め方・tools/nwp_mark.py の grid と check で確かめるのは 4 と同じ。必ず確かめる)。
  ・summary: 新しい図で分かった事を、関係するエリアの行に反映する(地上の低気圧・前線の動き、航空路の断面の変化。形は 4 と同じエリアごと)。変わらない所はそのまま。
  ・claims: 新しい図で予想が変わった物だけ直す・足す(id は前の物を残し、足す物は続きの番号)。from・to は今から 24 時間先まで。
  ・他の図の行で、新しい図と食い違う事を書いている所があれば直す。
  ・前の解説(どの図の行・summary・claims でも)に、今の決まりに合わない所(会社経路に無い路線・空域が主の行、SEV、「東回り」のようなあいまいな場所、風向の無い向かい風・追い風など)があれば、新しくなった図でなくても一緒に直す・消す(行を消したら、その図の印の番号もそろえる)。
  ・lm: 見直した図の lm を charts.json の今の lm に置き換える(他の図はそのまま)。at は今の UTC。
- 書く場所は 5・6 と同じ(ai.json と nwp_ai/history/<回の base から : を除いた物>.json を同じ中身で上書き。verify_log.md・lessons.md は、新しい図で読み方の注意が分かったときだけ足す)。コミットのメッセージ例: "nwp ai <base> update spas,fxjp106"。
- 最後に、どの図が新しくなり、何が変わったかを 1〜3 行で報告して終わる。

## 注意
- 図は気象庁の公開データ。秘密の情報は扱わない。APIキーやトークンをファイルに書かない。
- 図が読めない・壊れているときは、ai.json を書かずに、その理由を報告して終わる。
- 図の出る時刻(UTC。nwp-img には毎時 22 分に入る): 高層 03:36・15:36、AXJP 01:50・13:50 ごろ、SPAS・FXJP106 は 3 時間ごと(初期時刻の 2 時間ほど後)、FSAS24 07:08・19:03。
- 解析は main に push するとすぐ GitHub Actions が取り込み(nwp_ai/ai.json の push で動く)、アプリの WX保存で反映される。アプリでは marks が図に色付きで描かれ、解説の ①② の行と結び付く。check・verify はアプリに出さない(内部の記録)。
- claims(cat・cb・other で fl がある物)は、Map の「AI解析」として、断面図で経路が box を通る所に箱で出る(時間は from〜to)。断面図の札には text の中の強さ(LGT- 〜MOD)・「MOD の可能性」(→「LGT〜MOD?」。MOD の決まりを守る)・CB の雲頂・「山岳波」がそのまま出て、押すと text の全文が出る。だから text には強さを 1 つの書き方でだけ書く(「LGT〜LGT+」と「MOD」を別々に書いて食い違わせない)。
